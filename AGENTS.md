# ДОПОЛНЕНИЕ А — ЦЕЛОСТНОСТЬ ПЕРЕДАЧИ И ГЕЙТЫ (обязательно)

А1. Целостность кода
Селекторы и строки, содержащие "_", писать в коде ТОЛЬКО конструкцией
  через String.fromCharCode(95).
После сохранения файла проверить на диске: ключевые строки (селекторы,
  CTX_BUILD, version) совпадают с заданием дословно. Проверка — поиском
  по файлу (Select-String), не «глазами». При несовпадении — переписать
  строку вручную и проверить повторно.

А2. Репозиторный гейт
Каждое задание заканчивается коммитом в рабочую ветку (ветку указывает
  задание). Хэш коммита — в отчёте.
Не отчитываться «выполнено», пока файлы не закоммичены:
  проектировщик верифицирует raw-файлы на GitHub.

А3. Сборка и версии
Исходники в EdgeExtension/, артефакт в dist/. После правок кода ВСЕГДА
  выполнять Build.
Поднимать manifest version и CTX_BUILD строго до значений из задания;
  оба значения — в отчёте. Пользователь сверяет загруженную сборку по ним.

А4. Самодиагностика
coverage-логи и иные самопроверки, предписанные заданием, не удалять  и не «упрощать».
При доступном CDP: до отчёта прочитать консоль тестовой страницы и
  приложить ключевые строки в reports/v_XX/evidence/.
НЕ выдавать пользователю код для ручной вставки в консоль.
  Диагностика — файлами в scripts/diag/ или через CDP.

А5. Контракты
Перед заданием, затрагивающим storage/UI/карточку, прочитать действующий
  контракт в docs/architecture.md («Карточка базы — контракт v2»).
Имена и типы полей не менять без задания проектировщика.

А6. Полная замена файла
Переписывать файл целиком ТОЛЬКО если задание явно говорит
  «заменить целиком». Иначе — локальная правка (базовое правило).
